# Медиатека колледжа

Учебный проект для практики ПМ 03 «Ревьюирование программных продуктов».
Требования к поведению: docs/specification.md. В исходном состоянии есть учебные дефекты.
Неуспешные проверки являются исходными наблюдениями, которые нужно исследовать.

## Подготовка и запуск в Windows

Требуются Python 3.11 или новее и Git. Проверенная преподавателем версия Python используется всей группой.
Команды выполняйте из папки проекта в терминале VS Code. Активация окружения не нужна.

```text
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.venv\Scripts\python.exe app.py
```

Откройте http://127.0.0.1:5000 . Остановка сервера: Ctrl+C.
Если команды py нет, замените первую команду на python -m venv .venv.
На Linux/macOS вместо .venv\Scripts\python.exe используйте .venv/bin/python.
Если интернет ограничен, преподаватель заранее выдаёт совместимый набор wheel-пакетов:

```text
.venv\Scripts\python.exe -m pip install --no-index --find-links wheelhouse -r requirements-lock.txt
```

## Проверки

Остановите сервер либо откройте второй терминал и выполните:

```text
.venv\Scripts\python.exe -m pytest -q
.venv\Scripts\python.exe -m ruff check .
.venv\Scripts\python.exe -m radon cc catalog.py -s -a
.venv\Scripts\python.exe -m radon raw catalog.py
```

Проверка базовой логики без внешних библиотек: python tools/offline_selfcheck.py.
Снимок состояния: python tools/monitor_snapshot.py.

## Работа в GitFlic

Преподаватель создаёт проект GitFlic и выдаёт точный адрес клонирования и права участникам.
Одна пара работает в общем репозитории, у каждого своя учётная запись и свои ветки.
Создайте проблему по шаблону docs/templates/issue.md, затем ветку fix/номер-краткое-имя.
После локальных проверок выполните push и создайте запрос на слияние в main.
Скопируйте docs/templates/merge_request.md в описание, назначьте напарника рецензентом.
Получите ревью, ответьте на замечания и повторите проверки. Слияние выполняйте по правилам преподавателя.
Каждый студент выполняет минимум два собственных запроса и два ревью за всю практику.

Заготовки описаний копируются вручную. Папка docs/templates не настраивает интерфейс GitFlic автоматически.

## Состав

app.py — веб-приложение; catalog.py — логика каталога; data — данные; templates — HTML;
static — оформление, сценарий измерений и тестовые медиа; tests — тесты;
docs — требования и шаблоны; reports/block01 ... block07 — результаты блоков.

## Медиа

Образцы sample.mp4 и sample.webm содержат один синтетический 12-секундный сюжет для сравнения проигрывателей.
Фактический состав комплекта указан в static/media/README.md.
Субтитры sample.vtt предназначены для браузера, sample.srt — для VLC.

## Данные и доступ

Используйте вымышленные логины. Токены, ключи, реальные пароли, личную историю браузера и профили в репозиторий не добавляйте.
Скриншоты перед сдачей проверьте на отсутствие личных данных.

## Дополнительный стенд рекламы

Откройте /ads. Страница содержит безопасную имитацию вставки без внешних запросов.
Тестовое правило на странице применимо только к расширению, которое поддерживает свои фильтры.
Результат такого опыта относится к заданному правилу, а не ко всем спискам рекламы или защите от трекеров.

## Воспроизводимое окружение

requirements-lock.txt фиксирует проверенные версии. Комплект проверен на Windows x64 с Python 3.13.1.
Для другой ОС или версии Python установите зависимости по сети и проведите проверку на учебном компьютере.
Офлайн-архив пакетов преподавателя предназначен для Windows x64 и CPython 3.13.
